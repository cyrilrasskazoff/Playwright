Playwright позволяет перехватывать сетевой трафик с помощью метода page.on() и наблюдать, какими запросами и ответами
обмениваются в рамках выполнения нашего скрипта клиент и сервер.

******************
Модифицировать запрос
1. прерывание запроса
Например можем захотеть заблокировать загрузку ненужных элементов, чтобы ускорить процедуру и снизить использование
полосы пропускания.
Рассмотрим вариант прерывания запросов к данным сайта, если это изображения
page.route("**/*.{png,jpg,jpeg}", lambda route: route.abort())
- page.route() - функция позволяющая обрабатывать сетевые запросы. В отличие от page.on метод route может изменять сетевые
запросы и ответы
- **/*.{png,jpg,jpeg} -  шаблон url для соответствия маршрутизации. В качестве шаблона можно использовать RegExp, либо
целый url.
- lambda route: route.abort() -  это функция обработчик для маршрутизируемых запросов. Встроенный в playwright метод
route.abort()прерывает запрос по маршруту.

2. модификация запроса
модифицируем  запрос при обращении к эндпоинту api/register .
При нажатии на кнопку Register - successful происходит POST запрос с жестко прописанными учетными данными

Представим, что нам необходимо изменить передаваемые данные. Для этого используете метод  route.continue_  с аргументом
post_data
page.route("**/register", lambda route: route.continue_(post_data='{"email": "user","password": "secret"}'))

3. Модифицировать ответ - Mock
В качестве среды для тестирования мы будем использовать  веб-приложение блог -  realworld.io
В данном приложении есть область тегов:
Список этих тегов приходит ответом от GET запроса к https://api.realworld.io/api/tags
Наша задача - заменить этот список тегов на свой.
Во-первых, нам нужно понять в каком виде приходит информация по тегам. Это json у которого один ключ "tags", значением
его является массив, в котором и перечисляются теги которые в дальнейшем и отображаются в UI.
Во-вторых,  нужно создать такой же json, но уже со своими значениями. Именно этим json мы будем менять реальный ответ от
сервера.
Для  подмены ответа используется метод route.fulfill() в котором указывается путь до json с подменными данными.
def test_mock_tags(page):
    page.route("**/api/tags", lambda route: route.fulfill(path="data.json"))
    page.goto('https://demo.realworld.io/')

Другой вариант решения данной задачи - использование метода route.fetch и опции json для route.fulfill (с версии 1.29)
Мокинг данных в данном случае делится на три этапа:
1. Получить исходные данные с сервера.
2. Изменить полученные данные в формате json к нужному для вас значению.
3. Выполнить запрос с измененными данными.
Метод route.fetch() выполняет запрос на сервер и получает результат на данный запрос.  Вы можете работать с полученным
ответом как с json объектом.  С помощью метода route.fulfill и опции json, отправьте запрос с исправленным телом ответа.
В тестовом примере ниже, для выполнения трех этапов mocking создана функция-обработчик handle_route

def test_intercepted(page):
    def handle_route(route):
        response = route.fetch()
        json = response.json()
        json["tags"] = ["open", "solutions"]
        route.fulfill(json=json)

    page.route("**/api/tags", handle_route)

    page.goto("https://demo.realworld.io/")
    sidebar = page.locator('css=div.sidebar')
    expect(sidebar.get_by_role('link')).to_contain_text(["open", "solutions"])

Работа с HAR
HAR (HTTP Archive) - это формат файла, который используется для записи и хранения данных о взаимодействии браузера с
веб-сервером.

Запись HAR с помощью CLI:
Откройте браузер с помощью  команд cli и передайте опцию --save-har для создания файла HAR. Необязательным параметром
можно использовать аргумент  --save-har-glob для сохранения только интересующих вас запросов.
playwright open --save-har=example.har --save-har-glob="**/api/**" https://reqres.in

Просмотр HAR
Для просмотра файлов формата HAR можно воспользоваться специальными инструментами. Например, в браузере Google Chrome
можно использовать встроенный инструмент Network -> "стрелка вверх: Import HAR"
Также существует множество сторонних инструментов для работы с файлами HAR, например
https://toolbox.googleapps.com/apps/har_analyzer/?lang=ru

Подмена ответов из HAR
Если мы хотим использовать записанные ответы при следующем запуске теста, все, что нам нужно сделать, это добавить
следующую строку: page.route_from_har("example.har")
