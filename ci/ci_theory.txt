Pipeline в контексте CI/CD представляет собой последовательность автоматизированных этапов, которые выполняются один
за другим для вывода кода из репозитория исходного кода в производственную среду.
Структура Pipeline
Типичный pipeline обычно состоит из следующих этапов:
- Триггер: Pipeline запускается триггером, (например, коммит в репозиторий, расписание или ручной запуск).
- Сборка: Код собирается путем объединения всех необходимых компонентов, включая зависимости и конфигурации.
- Тестирование: Собранный код проверяется на наличие ошибок с помощью различных тестов, (модульные, интеграционные и т.д.)
- Развертывание: Прошедший тестирование код развертывается в определенной среде

Git
Установите Git на Mac
У большинства версий macOS уже Git установлен, и вы можете активировать их через терминал с помощью команды:
git version.

Первое, что вам следует сделать после установки Git - указать ваше имя и адрес электронной почты. Это важно, потому что
каждый коммит в Git содержит эту информацию, и она включена в коммиты, передаваемые вами. Откройте терминал и выполните
следующие команды:
git config --global user.name "Name" --- укажите ваше имя
git config --global user.email name@example.com --- укажите вашу почту

Проверьте, что настройки сохранились выполнив команду:
git config --list

Основные компоненты GitHub Actions
- Workflows. Workflow — это конфигурируемый автоматизированный процесс, который запускает один или
несколько jobs (задач). Workflows определяются файлами YAML, которые хранятся в директории .github/workflows репозитория.
Workflow может запускаться по событиям в репозитории, вручную или по расписанию.

- Events. Событие — это конкретное действие в репозитории, которое запускает выполнение workflow. Например, событие может
возникнуть при создании pull request, открытии issue или отправке коммита в репозиторий​ ​.

- Jobs. Job — это набор шагов (steps), которые выполняются на одном runner (сервере). Каждый шаг может быть либо shell
скриптом, либо action (действием). Шаги выполняются последовательно и могут зависеть друг от друга. Jobs могут выполняться
параллельно или последовательно, в зависимости от настроеk.

- Actions. Action — это настраиваемое приложение для платформы GitHub Actions, которое выполняет сложные, но часто
повторяющиеся задачи. Actions можно использовать для уменьшения объема повторяющегося кода в workflow файлах. Их можно
найти в GitHub Marketplace или написать самостоятельно

- Runners (Серверы) Runner — это сервер, который выполняет ваши workflows при их запуске. GitHub предоставляет готовые
runners с поддержкой Ubuntu, Windows и macOS. Также можно использовать собственные runners, если требуется специфическая
конфигурация оборудования или операционная система
