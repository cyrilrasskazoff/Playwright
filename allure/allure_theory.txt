Зачем нужен Allure Report?

- Визуализация результатов тестирования: Allure создает красивые и информативные отчеты
- Поддержка различных фреймворков: Allure интегрируется с множеством тестовых фреймворков (pytest, JUnit, TestNG...)
- Улучшение сотрудничества в команде
- Автоматизация отчетов: Allure можно интегрировать с CI/CD системами для автоматической генерации отчетов после каждого
запуска тестов.

Основные возможности Allure Report:
- Генерация отчетов: Allure автоматически генерирует отчеты на основе данных тестирования.
- Аннотации и метаданные: Возможность добавления метаданных и аннотаций к тестам для улучшения отчетов.
- Поддержка CI/CD: Интеграция с Jenkins, TeamCity и другими системами CI/CD.
- Исторические данные: Возможность отслеживания исторических данных тестов для анализа трендов
https://allure-framework.github.io/allure-demo/5/

Установка Allure
1. Убедитесь, что Homebrew  установлен.
2. В терминале:
brew install allure
3. Запустите эту команду, чтобы проверить, соответствует ли она последней версии:
allure --version

Интеграция Allure Report с проектами на pytest
Чтобы интегрировать Allure Report с проектом на pytest, выполните следующие шаги:

Установка плагина allure-pytest: Для этого используйте pip:
pip install allure-pytest

И не забудьте добавить новый зависимость в requirements.txt:
allure-pytest

Настройка pytest:
При запуске тестов укажите путь к каталогу результатов тестирования  --alluredir  в аргументе командной строки
pytest --alluredir=reports

Либо в файле конфигурации pytest ( pytest.ini ) добавьте следующие настройки:
[pytest]
addopts = --alluredir=reports
Эта настройка указывает pytest сохранять результаты тестов в директорию reports.

!!!!!
Чтобы сгенерировать и сохранить отчет:

В терминале выполните команду:
allure generate <путь_к_папке_с_результатами> -o <путь_для_отчета>
После генерации HTML-отчета, его можно открыть в браузере по указанному пути.

Чтобы сгенерировать отчет во временную директорию (без сохранения):
allure serve <путь_к_папке_с_результатами>

Использование аннотаций Allure в тестах

- Набор аннотаций для осуществления группировки дерева тестовых сценариев. Аннотации следуют подходу Agile.
@allure.epic  определяет задачу самого высокого уровня, которая будет разложена на feature
@allure.feature группирует тесты по проверяемому функционалу.
@allure.story группирует тесты по User story

import allure

@allure.epic("Web interface")
@allure.feature("Доступ к системе")
@allure.story("Авторизаци")
def test_authentication():
    pass

- Набор аннотаций добавляющий описание и другие метаданные
@allure.title Задает название теста.

- @allure.description Добавляет описание к тесту. Произвольный текст, описывающий тест более подробно, чем может
поместиться в  title.

- @allure.severity: Аннотация указывает на уровень важности теста
import allure

@allure.severity(allure.severity_level.CRITICAL)
def test_example():
    pass

- @allure.step Описывает шаг теста.
import allure

def test_annotated():
    with allure.step("Шаг 1"):
        assert True

чтобы отчет allure был доступен на github, мы будем использовать GitHub Pages. Приступим к настройкам репозитория:
На странице репозитория на GitHub перейдите в Settings → Actions → General.
В разделе Workflow permissions выберите параметр Workflow permissions -> Read and write permissions -> Save

Настройка публикации  отчета на GitHub Pages:
После выполнения тестов,  GitHub Action будет отправлять отчет Allure в специально созданную ветку из которой будет он
будет публиковаться с помощью сервиса GitHub Pages.

Давайте создадим ветку в которой будет храниться отчет:
Откройте репозиторий на GitHub -> Слева нажмите Branch -> New branch -> имя ветки = gh-pages -> Create new branch

Далее необходимо указать в настройках репозитория, какая ветка будет использоваться для GitHub Pages:
На странице репозитория на GitHub перейдите в Settings → Pages -> Build and deployment -> Source: “Deploy from a branch” ->
-> Branch:  gh-pages -> Save

Далее нужно обновить файл .github/workflows/playwright.yml

Публикация отчета после отправки изменений на GitHub может занять до 10 минут. Чтобы просмотреть опубликованный отчет
откройте настройки Settings → Pages. , в разделе GitHub Pages нажмите Visit site
